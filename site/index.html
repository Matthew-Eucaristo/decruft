decruft is the Storage screen developers never got. One scan shows everything your machine has piled up: Xcode simulators, Go and Homebrew caches, Docker, the Android SDK, node_modules, Cargo targets, Flutter builds and forgotten agent worktrees. Then it removes only what you pick, through each tool's own command, and measures what it actually freed.

Receipt

The bars spring to their new sizes and free space is measured from the disk, before and after. Trash, freed-now and delegated are kept apart, because they mean different things.

What it covers

One official command per area. Shown before it runs.

Built-in modules only offer what a tool can remove with its own documented command. No command means the item is shown with the owner's way to remove it, and never acted on. Every source is listed in docs/modules.md.

Every byte is offered once. When two sources report the same folder, or one inside another, the built-in module wins, then the outer item. So fell's worktree hides nodekill's node_modules inside it, and a Tauri app's src-tauri/target is rustkill's, not nodekill's.

What macOS does not show you

“System Data” is not an answer.

Settings lumps developer data into “Developer” and “System Data”, and counts purgeable space as free. decruft opens the box.

  • Free space as the filesystem reports it (statfs). Every before/after number uses it.
  • Purgeable space: what macOS can free by itself, and what Finder quietly adds to “available”.
  • Inside System Data: simulator runtimes (often several GB each), swap files and APFS local snapshots. Shown, never touched.
  • The Trash, which still takes space until emptied. Without Full Disk Access, decruft says so instead of guessing.
  • What removal frees now: on APFS, blocks shared with clones and snapshots are left out, so a pnpm store or a cloned worktree is not over-promised.

Safety model

Built to be trusted with your disk.

Cleaners earn their reputation by what they refuse to do. decruft fails closed, everywhere.

⌘The official way only

Caches go through their own tool's command, folders without one go to the Trash, family items go back to their own tool. sudo commands and apps that manage their own data are shown, never run.

⎔Pinned to what you saw

Every item carries a fingerprint of its state: path, folder identity, level, command. Right before acting, decruft re-reads it, refuses on any change, and acts on the fresh copy only.

◉Live means hands off

DerivedData while Xcode runs, a booted simulator or its runtime, the SDK while Android Studio runs: shown as live, never selectable.

⌫Trash by default

Folders go to the Trash, where Put Back restores them. --permanent deletes instead. Official commands delete by design, so the plan and the receipt keep them apart.

⊘Fail closed

An unknown safety level, unreadable tool output or another contract version: the item is protected or the source is skipped, with a warning. Never a guess.

⛬Guarded folder moves

Absolute paths, inside your home folder, at least three levels deep, never through a symlink. Commands run by absolute path with fixed arguments, stdin closed, never through a shell.

◌Read-only modes

--list, --json and --dry-run never change anything. --yes takes safe items only, never review ones.

∅No residue, no network

decruft writes no config, cache or state and never contacts the network itself. Uninstall it and nothing is left behind.

Three numbers that mean three different things, never summed into one flattering total. Free space is measured, not estimated.

The family

One umbrella. Specialists underneath.

decruft is the front door to four focused cleaners. brew install brings them along; decruft runs them in parallel through a versioned JSON contract and hands items back by {id, fingerprint} only, so each tool re-checks with its own rules. Each one also works on its own.

decruftcapabilities --json · scan --json · apply --plan -

fell

Fells forgotten git and AI-agent worktrees. Hands back retire, or strip when only that is allowed.

github.com/Matthew-Eucaristo/fell →

rustkill

Clears Cargo target folders it recognises by Cargo's own tag, Cargo's caches, and rustup toolchains, through rustup and cargo uninstall.

github.com/Matthew-Eucaristo/rustkill →

nodekill

Kills node_modules, framework and package-manager caches, and Node versions you no longer use.

github.com/Matthew-Eucaristo/nodekill →

flutterkill

Clears Flutter and Dart build outputs plus pub, Gradle, FVM and Android Studio caches. Filed by kind: Gradle → Android, Xcode → Xcode.

github.com/Matthew-Eucaristo/flutterkill →

The contract is public: fell's contract. Unknown schema means the source is skipped with a warning. decruft never passes --force or --unlock.

Use

Interactive when you want it. Scriptable when you don't.

Plain table when output is not a terminal, JSON for your own tooling (home paths written as ~/…), headless cleaning of safe items for the brave. Fits 40 columns, and NO_COLOR switches to glyphs only.

# interactive
decruft
# interactive, but nothing changes
decruft --dry-run
# plain table, read-only
decruft --list
# machine-readable, read-only
decruft --json | jq '.items[0]'
# headless: clean every safe item (never review items)
decruft --yes
# roots for fell, rustkill, nodekill, flutterkill (default ~/dev)
decruft ~/work ~/side
# built-in modules only
decruft --no-family

Install

One command. The whole family.

$brew install matthew-eucaristo/tap/decruft

Recommended on macOS and Linux. Homebrew installs fell, rustkill, nodekill and flutterkill as dependencies, and decruft runs them for their areas.

$go install github.com/Matthew-Eucaristo/decruft@latest

Needs Go 1.26+. Then install the family tools you want; decruft finds them on PATH and skips the ones that are missing.

Download from GitHub Releases →

Archives for macOS, Linux and Windows on amd64 and arm64, with checksums.txt. Windows runs the cross-platform modules.

macOSfirst-class: Xcode, simulators, purgeable, snapshots, Trash
Linuxsupported: apt, journald and Flatpak join the cross-platform modules
Windowscross-platform modules: Go, packages, Docker, Android, family
Uninstalling is just as clean 
brew uninstall decruft && brew autoremove   # also removes the family tools if only decruft needed them
brew untap matthew-eucaristo/tap            # if you no longer use the tap

decruft writes nothing to your disk, so there is nothing else to remove. With go install: rm "$(go env GOPATH)/bin/decruft".

Questions

Fair questions.

Will it delete something I need?

Only what you select, and only through the owning tool's documented command or a move to the Trash. Anything that needs judgement is marked ▲ review and is never taken by s or --yes. Archives, Gradle and anything behind sudo are shown with instructions and never acted on.

Why not just rm -rf ~/Library/Developer?

Because tools keep state about their own files. Go's module cache is read-only, so plain rm fails half-way; uv's cache goes inconsistent if you delete it by hand; simulator runtimes are registered with CoreSimulator. The official command is the one that leaves the tool in a correct state.

Why does it say “claimed, not freed”?

Because decruft measures free space before and after with statfs. If a command frees far less than it promised (APFS clones, snapshots holding blocks), the receipt says so instead of repeating the promise.

Does it phone home?

No. decruft makes no network requests and keeps no state. Commands it runs get a quiet environment (HOMEBREW_NO_AUTO_UPDATE, NO_COLOR, PIP_NO_INPUT…) so nothing updates itself either. This page loads nothing from third parties, too.

Do I need fell, rustkill, nodekill and flutterkill?

No. Homebrew installs them for you, but decruft skips any that are missing, and --no-family uses built-in modules only.

How is this different from other Mac cleaners?

It is a developer tool, not a system tuner: it knows what Xcode, Go, Homebrew and Docker are, uses their commands, explains every item, and proves the result with a measured receipt. Open source, MIT, a single binary you can audit.

I found a bug that touches the wrong thing.

That is a security issue. Please report it privately through GitHub Security Advisories, not a public issue.
